### Оптимизация поиска и группировки шин - переход на SQL-группировку

**Описание:** Оптимизирована функция `search_tire_nomenclature` в `tires/utils.py` для использования SQL-уровневой группировки вместо Python-циклов.

**Причина:**
Старая реализация группировки шин происходила в Python-коде после получения всех результатов из базы данных. Это приводило к:
1. Загрузке всех шин в память (даже если потом они группируются)
2. Медленной сортировке и обработке для больших выборок
3. Невозможности эффективной сортировки по точности совпадения

**Решение:**
1. Перенесена группировка на уровень SQL через `values() + annotate(Count())`
2. Добавлено вычисление `nomenclature_key` прямо в SQL через `Concat`
3. Реализована сортировка по точности совпадения через `Case/When` (match_score)
4. Добавлено поле `warehouse` и `supplier` в группировку для корректной идентификации

**Изменения:**

**Статус:** ✅ Изменён `tires/utils.py`
- Добавлены импорты: `Value`, `Case`, `When`, `F`, `Concat`, `CharField`, `IntegerField`
- Добавлен импорт `Warehouse`, `Supplier` из моделей
- Переписана функция `search_tire_nomenclature()`:
  - Группировка происходит на уровне SQL (`values().annotate(Count())`)
  - Вычисление `nomenclature_key` через `Concat` в SQL
  - Фильтрация по `nomenclature_key__icontains` для поиска
  - Вычисление `match_score` для сортировки по точности совпадения:
    - Полное совпадение (`iexact`) → 100 баллов
    - Начинается с запроса (`istartswith`) → 50 баллов
    - Содержит запрос (`icontains`) → 25 баллов
    - По умолчанию → 1 балл
  - Сортировка: сначала по `match_score`, потом по `count`
  - Добавлены поля `warehouse` и `supplier` в группировку
  - Оптимизированы запросы к складам и поставщикам через словари

**Логика:**
```
SQL-запрос (пример):
SELECT 
    size, brand, model, 
    warehouse_id, supplier_id,
    COUNT(*) as count,
    CONCAT(size, ' ', brand, ' ', model) as nomenclature_key,
    CASE
        WHEN nomenclature_key = '205/55 R16 Michelin X' THEN 100
        WHEN nomenclature_key LIKE '205/55 R16%' THEN 50
        WHEN nomenclature_key LIKE '%205/55 R16%' THEN 25
        ELSE 1
    END as match_score
FROM tires_tire
WHERE is_active = TRUE AND warehouse_id = 1
GROUP BY size, brand, model, warehouse_id, supplier_id
ORDER BY match_score DESC, count DESC
```

**Преимущества:**
- ✅ Группировка происходит в базе данных (оптимально)
- ✅ Не загружаются все шины в память
- ✅ Сортировка по точности совпадения работает
- ✅ Сортировка по количеству работает
- ✅ Масштабируемость для тысяч шин
- ✅ Меньше времени выполнения для больших данных

### Исправление HTMX поиска в модальном окне

**Описание:** Поиск в модальном окне добавления товара не работал — всегда возвращал полный список шин, не зависимо от введённой подстроки.

**Причина:**
В HTMX input для поиска отсутствовал атрибут `name="q"`. Без этого атрибута HTMX не передаёт значение поля в GET запросе, поэтому `request.GET.get('q', '')` всегда возвращал пустую строку ''.

**Решение:**
Добавлен атрибут `name="q"` в input поля для поиска шин в модальных окнах.

**Изменения:**

**Статус:** ✅ Изменён `templates/warehouse/partials/document_modals.html`
- Добавлен атрибут `name="q"` в input поля для поиска
- HTMX теперь корректно передаёт значение в GET параметр `q`

**Логика работы:**
```
1. Пользователь вводит запрос в поле поиска (например, "AEOLUS")
2. HTMX делает GET запрос к /tires/search/?q=AEOLUS&warehouse=1
```
