РАЗДЕЛ 1. ГРАНИЦЫ ПРОЕКТА (MVP)
================================================================================

1.1. В СОСТАВЕ MVP
--------------------------------------------------------------------------------
- Ручная загрузка файла с DataMatrix-кодами (текстовый формат, по коду на строку)
- Выбор склада перед загрузкой (ручная приписка кодов к конкретному складу)
- Запрос данных по каждому коду в «Честный знак» через библиотеку nechestniy_znak (реализовано)
- Парсинг атрибутов шин: brand, model, size, product_name (реализовано)
- Авто-создание номенклатуры при первом встреченном сочетании brand + model + size
- Хранение кодов с атрибутами, дедупликация по значению кода (любой статус → пропуск)
- Логирование процесса загрузки
- Отчёт по итогам загрузки: создано / пропущено-дубликат / пропущено-нераспознано / пропущено-ошибка «Честного знака»
- Список пропущенных кодов со значениями и причинами пропуска
- Управление пользователями: начальник склада / кладовщик
- Создание документов списания и выкупа
- Жизненный цикл: черновик (не сохранён) → сохранён → проведён → распроведён / помечен на удаление
- Экранное отображение кодов только после проведения документа
- Счётчики активных кодов по позициям и складам
- Фильтрация документов по площадке-источнику документа и площадке-источнику списания
- Автосохранение черновика при разрыве соединения
- Карточка кода: текстовый код в две строки + номенклатура (производитель + модель + размер) + DataMatrix-код, размер — сопоставим со спичечным коробком в книжном формате

1.2. ВНЕ СОСТАВА (ОТЛОЖЕНО)
--------------------------------------------------------------------------------
- API-интеграция с 1С (автоматическая ежедневная загрузка)
- Печать кодов на А4
- Нешины (другие товарные категории)
- Реальный складской учёт остатков ТМЦ
- Вторая площадка «Софийская Легковой» — архитектура учитывает, реализация отложена
- Автоматический маппинг владелец → склад (в MVP — ручная приписка)

РАЗДЕЛ 2. БИЗНЕС-ПРАВИЛА
================================================================================

| №  | Правило                                    | Решение |
|----|--------------------------------------------|--------|
| 1  | Авто-создание номенклатуры                 | Создаётся автоматически при первом сочетании brand + model + size. Неполные атрибуты → код пропускается как нераспознанный |
| 2  | Нераспознанные коды                        | Пропускаются, логируются, попадают в отчёт о загрузке со значением кода и причиной пропуска |
| 3  | Дедупликация                               | Проверка по значению кода, любой статус → пропуск, повторный запрос в «Честный знак» не отправляется |
| 4  | Маппинг владелец → склад                   | В MVP — ручная приписка к складу при загрузке, без автоматического маппинга |
| 5  | Экранное отображение                       | Только после проведения документа, до проведения — недоступно |
| 6  | Параллельная работа                        | Без резерва. Конфликт обнаруживается при проведении — атомарная транзакция. Кто первым провёл — забрал коды |
| 7  | FIFO                                       | По дате загрузки в систему, внутри дня — по ID (автоинкремент) |
| 8  | Выкуп                                      | Приписка меняется локально, без перезапроса «Честного знака» |
| 9  | Редактирование проведённого                | Запрещено. Для изменений — распроведение в статус «Сохранён» |
| 10 | Помечен на удаление                        | = распроведение + is_deleted = true |
| 11 | Начальник — чужие площадки                 | Только чтение |
| 12 | Кладовщик — чужие документы                | Не видит, не редактирует |
| 13 | Списание с чужой площадки                  | Разрешено, документ на имя создавшего кладовщика, счётчик уменьшается у площадки-источника списания |
| 14 | Заполнение product_name                    | Из ответа «Честного знака» при создании номенклатуры. Если нет — null, fallback: brand + model + size. Не перезаписывается при повторной загрузке. Ручное редактирование доступно начальнику (не для MVP) |
| 15 | Дубликаты номенклатуры в документе         | Запрещены. При попытке добавить существующую номенклатуру — подсветить существующую строку и увеличить количество в ней на 1. Предлагать объединение не нужно |
| 16 | Формат нумерации документов                | С годом и сбросом счётчика в начале года: СП-2026-000001 (списание), ВК-2026-000001 (выкуп). Номер присваивается при переходе из черновика в «Сохранён» |

РАЗДЕЛ 3. СТАТУСНАЯ МОДЕЛЬ ДОКУМЕНТА
================================================================================

3.1. СХЕМА СТАТУСОВ
--------------------------------------------------------------------------------

    Черновик (не сохранён) → Сохранён → Проведён
                               ↓                ↓
                         Помечен на       Распроведён
                         удаление         → Сохранён

3.2. КНОПКИ ПО СТАТУСАМ
--------------------------------------------------------------------------------

Статус: Черновик (не сохранён)
  - «Добавить строку» — вызывает список номенклатуры со строкой поиска
  - «Сохранить» — переводит в «Сохранён», присваивает номер
  - «Отменить» — сброс содержимого без сохранения, закрытие

Статус: Сохранён
  - «Добавить строку» — вызывает список номенклатуры со строкой поиска
  - «Сохранить» — перезаписывает состав
  - «Провести» — атомарная транзакция: проверка остатка → выбор кодов по FIFO → пометка использованными → уменьшение счётчиков → переход в «Проведён»
  - «Пометить на удаление» — распроведение + is_deleted = true

Статус: Проведён
  - «Распровести» — откат: возврат кодов в активные, восстановление счётчиков, переход в «Сохранён»
  - «Экранное отображение кодов» — показ закреплённых за документом кодов

Статус: Помечен на удаление
  - Только просмотр

3.3. АЛГОРИТМ ПРОВЕДЕНИЯ (АТОМАРНАЯ ТРАНЗАКЦИЯ)
--------------------------------------------------------------------------------
1. Для каждой строки документа: проверить, что запрошенное количество <= количества активных кодов по позиции на складе-источнике
2. Если хотя бы по одной строке нехватка — откатить транзакцию, вернуть ошибку с указанием позиции и доступного количества
3. Если по всем строкам достаточно — выбрать старейшие активные коды по FIFO (дата загрузки, внутри дня по ID), пометить «использован», привязать к документу
4. Уменьшить счётчики активных кодов по позициям и складам
5. Перевести документ в статус «Проведён»
6. При нехватке документ остаётся в статусе «Сохранён», кладовщик корректирует количество и повторяет проведение

РАЗДЕЛ 4. МОДЕЛИ ДАННЫХ
================================================================================

4.1. TIRE_NOMENCLATURE (Справочник номенклатуры)
--------------------------------------------------------------------------------
Назначение: справочник уникальных номенклатурных позиций шин. Создаётся автоматически при первой загрузке кода с новым сочетанием brand + model + size.

| Поле          | Тип             | Описание                                    | Ограничения  |
|---------------|-----------------|---------------------------------------------|--------------|
| id            | Auto (PK)       | Идентификатор                               |      —       |
| brand         | CharField(100)  | Производитель (бренд)                       | Обязательное |
| model         | CharField(100)  | Модель продукта                             | Обязательное |
| size          | CharField(50)   | Размер (например, 205/55 R15)               | Обязательное |
| product_name  | CharField(100)  | Наименование из «Честного знака»            | nullable. Если нет — fallback: brand + model + size. Не перезаписывается при повторной загрузке |
| is_active     | BooleanField    | Активность номенклатуры                     | По умолчанию True |
| created_at    | DateTimeField   | Дата создания                               | auto_now_add |
| updated_at    | DateTimeField   | Дата изменения                              | auto_now |

Ограничение уникальности: unique_together = (brand, model, size)

4.2. TIRE_CODE (Индивидуальный DataMatrix-код)
--------------------------------------------------------------------------------
Назначение: конкретный DataMatrix-код, привязанный к номенклатуре, складу и документу.

| Поле             | Тип               | Описание                                              | Ограничения |
|------------------|-------------------|-------------------------------------------------------|-------------|
| id               | Auto (PK)         | Идентификатор (используется для FIFO внутри дня)       | — |
| qr_code          | CharField(100)    | Значение DataMatrix-кода                              | unique=True |
| nomenclature     | FK → Tire_nomenclature | Ссылка на номенклатуру                            | on_delete=PROTECT |
| warehouse        | FK → Warehouse    | Склад, к которому приписан код                         | on_delete=SET_NULL, nullable |
| supplier         | FK → Supplier     | Поставщик (для складов ОХ)                             | on_delete=SET_NULL, nullable |
| is_active        | BooleanField      | Активен (не использован)                               | По умолчанию True |
| is_used          | BooleanField      | Использован (списан в проведённом документе)            | По умолчанию False |
| honest_sign_data | JSONField         | Полный ответ «Честного знака»                          | nullable |
| document         | FK → Document     | Документ, в котором код списан                         | on_delete=SET_NULL, nullable, related_name='codes' |
| created_at       | DateTimeField     | Дата загрузки в систему (для FIFO)                     | auto_now_add |
| used_at          | DateTimeField     | Дата пометки использованным                            | nullable |

Примечание: is_active и is_used — раздельные флаги. is_active = False означает «выбывает из системы», is_used = True означает «списан в документе». При проведении is_used → True, is_active → False. При распроведении — обратный откат.

4.3. PLATFORM (Площадка)
--------------------------------------------------------------------------------
Назначение: самостоятельная сущность «площадка». В MVP — одна: «Софийская Груз». Архитектура допускает множественные площадки.

| Поле       | Тип             | Описание              | Ограничения |
|------------|-----------------|-----------------------|-------------|
| id         | Auto (PK)       | Идентификатор         | — |
| name       | CharField(100)  | Название площадки    | unique=True |
| created_at | DateTimeField   | Дата создания         | auto_now_add |

4.4. WAREHOUSE (Склад) — дополненная версия
--------------------------------------------------------------------------------
Назначение: склад внутри площадки. Два типа: Основной (main) и Ответственное хранение (oh).

| Поле           | Тип              | Описание                                  | Ограничения |
|----------------|------------------|-------------------------------------------|-------------|
| id             | Auto (PK)        | Идентификатор                             | — |
| name           | CharField(100)   | Название склада                           | unique=True |
| warehouse_type | CharField(20)    | Тип: 'main' или 'oh'                      | choices |
| platform       | FK → Platform    | Площадка, которой принадлежит склад        | on_delete=CASCADE, related_name='warehouses' |
| supplier       | FK → Supplier    | Поставщик (только для складов ОХ)          | on_delete=SET_NULL, nullable |
| created_at     | DateTimeField    | Дата создания                             | auto_now_add |

4.5. SUPPLIER (Поставщик) — без изменений
--------------------------------------------------------------------------------
Назначение: поставщик для складов ответственного хранения.

| Поле       | Тип             | Описание              | Ограничения |
|------------|-----------------|-----------------------|-------------|
| id         | Auto (PK)       | Идентификатор         | — |
| name       | CharField(255)  | Название поставщика   | unique=True |
| created_at | DateTimeField   | Дата создания         | auto_now_add |

4.6. DOCUMENT (Документ списания/выкупа)
--------------------------------------------------------------------------------
Назначение: документ для списания или выкупа DataMatrix-кодов.

| Поле              | Тип              | Описание                                              | Ограничения |
|-------------------|------------------|-------------------------------------------------------|-------------|
| id                | Auto (PK)        | Идентификатор                                         | — |
| doc_type          | CharField(20)    | Тип: 'writeoff' (списание) или 'buyout' (выкуп)       | choices |
| number            | CharField(20)    | Номер документа                                       | Формат: СП-ГГГГ-NNNNNN / ВК-ГГГГ-NNNNNN. Присваивается при переходе в «Сохранён» |
| status            | CharField(20)    | Статус: 'draft' / 'saved' / 'posted' / 'marked_deleted' | choices |
| author            | FK → User        | Создатель документа                                    | related_name='documents' |
| source_platform   | FK → Platform    | Площадка-источник документа (кто создал)               | related_name='source_documents' |
| writeoff_platform | FK → Platform    | Площадка-источник списания (откуда списаны коды)        | related_name='writeoff_documents' |
| source_warehouse  | FK → Warehouse   | Склад-источник                                         | related_name='outgoing_docs' |
| target_warehouse  | FK → Warehouse   | Склад-получатель (Основной склад площадки кладовщика)   | related_name='incoming_docs', nullable |
| is_deleted        | BooleanField     | Пометка на удаление                                     | По умолчанию False |
| created_at        | DateTimeField    | Дата создания                                          | auto_now_add |
| updated_at        | DateTimeField    | Дата изменения                                         | auto_now |
| posted_at         | DateTimeField    | Дата проведения                                        | nullable |

Нумерация:
  - Списание: СП-2026-000001 (префикс СП, год, порядковый номер с нулями до 6 знаков)
  - Выкуп: ВК-2026-000001 (префикс ВК, год, порядковый номер с нулями до 6 знаков)
  - Счётчик сбрасывается в начале каждого года
  - Сквозная нумерация в пределах типа и года

Правила заполнения:
  - source_platform = площадка автора документа
  - writeoff_platform = площадка склада-источника (может отличаться от source_platform при списании с чужой площадки)
  - target_warehouse = Основной склад площадки автора (только для выкупа; для списания — null)

4.7. DOCUMENT_ITEM (Строка документа)
--------------------------------------------------------------------------------
Назначение: строка документа — номенклатура + количество. Дубликаты номенклатуры в рамках одного документа запрещены.

| Поле         | Тип                  | Описание                              | Ограничения |
|--------------|----------------------|---------------------------------------|-------------|
| id           | Auto (PK)            | Идентификатор                         | — |
| document     | FK → Document        | Документ                              | on_delete=CASCADE, related_name='items' |
| nomenclature | FK → Tire_nomenclature | Номенклатура                        | on_delete=PROTECT |
| quantity     | IntegerField         | Количество кодов к списанию           | Positive, default=1 |

Ограничение уникальности: unique_together = (document, nomenclature) — одна номенклатура — одна строка в документе

Поведение при добавлении дубликата:
  - Если номенклатура уже есть в документе — не создавать новую строку
  - Подсветить существующую строку
  - Увеличить quantity в существующей строке на 1
  - Предлагать объединение не нужно

4.8. USER (Расширение)
--------------------------------------------------------------------------------
Назначение: расширение стандартной модели User — привязка к площадке и роль.

| Поле    | Тип             | Описание                                    | Ограничения |
|---------|-----------------|---------------------------------------------|-------------|
| platform | FK → Platform   | Площадка, к которой привязан пользователь   | on_delete=SET_NULL, nullable |
| role    | CharField(20)   | Роль: 'manager' (начальник) / 'storekeeper' (кладовщик) | choices |

Права по ролям:
  - Начальник (manager): полный доступ к документам своей площадки; документы других площадок — только чтение
  - Кладовщик (storekeeper): только свои документы; может списывать коды с любой площадки

РАЗДЕЛ 6. ЛОГИРОВАНИЕ И ОТЧЁТНОСТЬ ПРИ ЗАГРУЗКЕ
================================================================================

Процесс загрузки файла:
1. Пользователь выбирает склад → загружает файл
2. Для каждой строки файла:
   a. Проверка на дубликат в базе (по значению qr_code, любой статус) → если есть: пропуск, запись в лог как «дубликат»
   b. Запрос в «Честный знак» (если код новый) → если ошибка: пропуск, запись в лог как «ошибка Честного знака»
   c. Парсинг атрибутов (brand, model, size) → если неполные: пропуск, запись в лог как «нераспознанный»
   d. Создание номенклатуры (если нового сочетания brand+model+size ещё нет)
   e. Создание TireCode с привязкой к номенклатуре, складу, поставщику
3. По итогам загрузки — отчёт:
   - Загружено и создано в базе: N кодов
   - Пропущено как дубликаты: M кодов
   - Пропущено как нераспознанные: K кодов
   - Пропущено по ошибке «Честного знака»: L кодов
4. Список пропущенных кодов: значение кода + причина пропуска
