## Введение

TireTrack — система управления шинами и кодами DataMatrix. Основные возможности:
- Загрузка и обработка QR-кодов из файлов
- Создание и проведение документов (списание, выкуп)
- Отслеживание кодов DataMatrix (Честный Знак)
- Дашборд с аналитикой

**Требования:**
- Авторизация в системе
- Роль: Manager или Storekeeper

---

## Дашборд

Дашборд доступен по адресу `/warehouse/`.

### Что отображается:
- **Всего кодов** — общее количество TireCode в вашей площадке
- **Активных кодов** — коды со статусом active=True, is_used=False
- **Использованных кодов** — коды, привязанные к документам
- **Документы по статусам** — draft, saved, posted
- **Последние документы** — 5 последних созданных документов

### Быстрые действия:
- Кликните на документ для просмотра деталей
- Используйте фильтры для поиска
- Перейдите к списку документов для создания нового

## Работа с документами

### Создание документа

1. **Перейдите к созданию:** `/warehouse/documents/new/`
2. **Выберите тип документа:**
   - Списание (prefix: СП-ГГГГ-NNNNNN)
   - Выкуп (prefix: ВК-ГГГГ-NNNNNN)
3. **Выберите склад отправления** (обязательно)
4. **Выберите склад назначения** (опционально для выкупа)
5. **Добавьте комментарии** (опционально)
6. **Нажмите "Создать"**

### Добавление строк в документ

После создания документа вы попадёте на страницу детального просмотра.

**Добавление номенклатуры:**
1. В блоке "Добавить строку" введите название/бренд/размер
2. Система автоматически найдёт совпадения через AJAX
3. Выберите нужную номенклатуру
4. Укажите количество (по умолчанию 1)
5. Нажмите "Добавить"

**Дедупликация:**
- Если номенклатура уже добавлена, количество увеличится
- Система покажет уведомление "Дубликат"

**Редактирование количества:**
- Измените значение в поле количества
- Нажмите Enter или кликните вне поля
- Количество сохранится автоматически

**Удаление строки:**
- Кликните на иконку удаления (🗑️)
- Строка будет удалена из документа

### Статусы документов

| Статус | Описание | Действия |
|--------|----------|----------|
| **draft** | Черновик, не сохранён | Можно редактировать, сохранить |
| **saved** | Сохранён, нумерация присвоена | Можно редактировать, провести |
| **posted** | Проведён, коды использованы | Можно распровести, посмотреть коды |
| **marked_deleted** | Помечен на удаление | Нельзя редактировать |

### Нумерация документов

Формат: `СП-2026-000001` или `ВК-2026-000001`

- **Префикс:** СП (списание) / ВК (выкуп)
- **Год:** ГГГГ
- **Счётчик:** NNNNNN (сбрасывается ежегодно)

### Проведение документа

**Важно:** Проведение использует FIFO (First In, First Out) — коды используются в порядке создания.

**Условия для проведения:**
1. Документ должен быть в статусе `saved`
2. Документ должен содержать хотя бы одну строку
3. Должно быть достаточно кодов на складе отправления

**Процесс:**
1. Убедитесь что все строки добавлены
2. Нажмите "Провести"
3. Система:
   - Присвоит номер документу
   - Выделит коды через FIFO
   - Обновит склады кодов
   - Изменит статус на `posted`

**При выкупе:**
- Коды перевязываются на target_warehouse
- Статус is_active остаётся True (коды не расходуются)

**При списании:**
- Коды помечаются как is_active=False, is_used=True
- Коды расходуются с склада

### Распроведение

Можно отменить проведение если документ ещё не использован:
1. Документ должен быть в статусе `posted`
2. Нажмите "Распровести"
3. Статус вернётся в `saved`
4. Коды вернутся на исходный склад (для списания)

### Просмотр кодов документа

После проведения можно посмотреть какие коды привязаны:
1. На странице документа нажмите "Коды"
2. Откроется экранное отображение с пагинацией (50 кодов на странице)
3. Можно фильтровать по номенклатуре
4. Кликните на код для просмотра карточки

### Пометка на удаление

**Внимание:** Нельзя пометить проведённый документ — сначала распроведите!

## Загрузка QR-кодов

### Импорт из файла

1. **Перейдите:** `/qr/imports/`
2. **Выберите склад** (обязательно)
3. **Выберите поставщика** (опционально)
4. **Загрузите файл** (.txt, одна QR-код на строку):
   ```
   00000046209849Uon<TYfACyAJPHJ
   00000046209850Vpo=UZgBDQzKQIK
   ```
   **ИЛИ** вставьте текст вручную

5. **Нажмите "Загрузить"**

### Обработка

Система:
1. Считывает каждый QR-код
2. Запрашивает данные из Честного Знака через `infoFromDataMatrix()`
3. Создаёт `TireCode` с привязкой к `TireNomenclature`
4. Автоматически создаёт номенклатуру если не существует

### Отчёт о загрузке

После загрузки отображается отчёт:
- **Всего строк** — количество строк в файле
- **Создано** — успешно созданных TireCode
- **Дубликаты** — QR-коды которые уже существуют
- **Нераспознанные** — неполные данные от Честного Знака
- **Ошибки ЧЗ** — ошибки запроса к API

**Пример отчёта:**
```
Всего строк: 100
Создано: 95
Дубликаты: 3
Нераспознанные: 1
Ошибки ЧЗ: 1
```

### Мок-режим для разработки

Для локальной разработки можно отключить запросы к Честному Знаку:
```bash
export USE_MOCK_HONEST_SIGN=True
```

В мок-режиме возвращаются тестовые данные:
- brand: "MockBrand"
- model: "MockModel"
- size: "295/80R22.5"

## Карточка кода

Карточка отображает полную информацию о TireCode.

### Доступ:
- Из экрана кодов документа (клик на QR)
- Прямая ссылка: `/warehouse/codes/<id>/card/`

### Что отображается:
- **QR-код (DataMatrix)** — изображение для сканирования
- **QR-код (текст)** — строковое представление
- **Бренд** — из номенклатуры
- **Модель** — из номенклатуры
- **Размер** — из номенклатуры
- **Наименование** — product_name
- **Склад** — текущий склад

### DataMatrix:
- Генерируется автоматически через `qrcode.make()`
- Формат: PNG
- Размер: 200px max-width

## Поиск номенклатуры

### AJAX поиск

Доступен при добавлении строк в документ.

**Параметры запроса:**
```
GET /warehouse/api/nomenclature/search/?q=Michelin&limit=20
```

**Примеры поиска:**
- По бренду: `q=Michelin`
- По модели: `q=X`
- По размеру: `q=205/55 R16`
- По наименованию: `q=Michelin X`

**Ответ API:**
```json
{
  "results": [
    {
      "id": 1,
      "display_name": "Michelin X",
      "brand": "Michelin",
      "model": "X",
      "size": "205/55 R16"
    }
  ]
}
```

**Особенности:**
- Поиск case-insensitive (`icontains`)
- Фильтр только по активным (`is_active=True`)
- Лимит результатов: по умолчанию 20

## API: Счётчики

### Получение количества активных кодов

**Запрос:**
```
GET /warehouse/api/counters-api/?warehouse=1&nomenclature=1
```

**Параметры:**
- `warehouse` — ID склада (опционально)
- `nomenclature` — ID номенклатуры (опционально)

**Ответ:**
```json
{
  "active": 42
}
```

**Критерии "active":**
- `is_active=True`
- `is_used=False`

## Частые вопросы

### Q: Почему нельзя редактировать проведённый документ?
**A:** Проведение изменяет статус кодов и складов. Редактирование после проведения привело бы к несоответствиям. Сначала распроведите документ.

### Q: Что делать если код не распознаётся?
**A:** Проверьте:
1. Корректность DataMatrix (должен быть в формате Честного Знака)
2. Доступность API Честного Знака
3. Полноту данных (brand, model, size должны быть заполнены)

### Q: Как работает FIFO при проведении?
**A:** Система использует коды в порядке создания (`order_by('created_at', 'id')`). Старые коды используются первыми.

### Q: Можно ли провести документ без строк?
**A:** Нет, документ должен содержать хотя бы одну строку (DocumentItem).

### Q: В чём разница между draft и saved?
**A:**
- **draft** — черновик, номер не присвоен
- **saved** — сохранён, номер присвоен (СП-2026-000001), нельзя удалить

### Q: Как сбросить счётчик нумерации?
**A:** Счётчик сбрасывается автоматически ежегодно. Новый год — новый счётчик с 000001.

### Q: Что делать если нужно удалить проведённый документ?
**A:**
1. Распроведите документ (`/warehouse/documents/<id>/unpost/`)
2. Пометьте на удаление (`/warehouse/documents/<id>/delete/`)

### Q: Как загрузить коды без подключения к Честному Знаку?
**A:** Используйте мок-режим: `export USE_MOCK_HONEST_SIGN=True`
