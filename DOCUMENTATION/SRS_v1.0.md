## 1. ВВЕДЕНИЕ

### 1.1. Назначение документа

Документ определяет полный набор требований к системе обработки DataMatrix-кодов шин. Система предназначена для загрузки индивидуальных маркировочных кодов, управления номенклатурой, создания документов списания и выкупа, а также экранного отображения кодов.

Документ является единым источником истины для команды разработки, тестирования и приёмки. Все остальные артефакты (User Stories, тест-кейсы, диаграммы, спецификация экранов, архитектурная спецификация, карта URL) подчинены данному документу и должны ему соответствовать.

### 1.2. Область действия

Система разрабатывается как веб-приложение на Django + Templates для внутреннего использования сотрудниками складов шин. MVP охватывает ручную загрузку кодов, документооборот списания и выкупа, экранное отображение.

### 1.3. Определения, акронимы и сокращения

| Термин | Расшифровка |
|--------|-------------|
| DataMatrix | Двумерный матричный штрих-код, используемый для маркировки шин |
| «Честный знак» | Государственная система маркировки и прослеживаемости товаров |
| FIFO | First In, First Out — метод выбора кодов по дате загрузки |
| MVP | Minimum Viable Product — минимально жизнеспособный продукт |
| Списание | Документ, оформляющий выбытие кодов со склада |
| Выкуп | Документ, оформляющий перевод кодов со склада ОХ на основной склад площадки кладовщика |
| ОХ | Ответственное хранение — тип склада |
| Площадка | Самостоятельная территориальная единица (в MVP — «Софийская Груз») |
| SRS | Software Requirements Specification — настоящий документ |
| HTMX | Библиотека для AJAX-взаимодействия без написания JavaScript |
| CSRF | Cross-Site Request Forgery — защита от подделки межсайтовых запросов |

### 1.5. Краткое описание системы

Система обеспечивает:
- Загрузку файлов с DataMatrix-кодами с автоматическим запросом атрибутов в «Честном знаке»
- Автоматическое создание справочника номенклатуры
- Управление документами списания и выкупа с полным жизненным циклом
- FIFO-распределение кодов при проведении документов
- Экранное отображение закреплённых кодов
- Управление пользователями и правами доступа по ролям

## 2. ОБЩЕЕ ОПИСАНИЕ

### 2.1. Перспективы продукта

Система является самостоятельным веб-приложением, не имеющим внешних потребителей в рамках MVP. В перспективе предусмотрена API-интеграция с 1С (автоматическая ежедневная загрузка кодов), однако в рамках текущей версии эта интеграция отложена.

### 2.2. Функции продукта

| Группа функций | Описание |
|----------------|---------|
| Загрузка кодов | Ручная загрузка файла, выбор склада, запрос в «Честный знак», дедупликация, авто-создание номенклатуры, отчёт |
| Документооборот | Создание, сохранение, проведение, распроведение, пометка на удаление документов списания и выкупа |
| Управление кодами | Хранение, FIFO-выбор, экранное отображение, карточка кода |
| Справочники | Номенклатура, склады, площадки, поставщики |
| Управление доступом | Роли (начальник, кладовщик), привязка к площадке, права по чужим документам |
| Отчётность | Отчёт по загрузке, счётчики активных кодов |

### 2.3. Характеристики пользователей

| Роль | Код | Описание | Права |
|------|-----|----------|-------|
| Начальник склада | `manager` | Управляющий площадкой | Полный доступ к документам своей площадки; чужие — только чтение. Управление пользователями. |
| Кладовщик | `storekeeper` | Операционный сотрудник | Только свои документы; списание с любой площадки. Создание и проведение документов. |

### 2.4. Ограничения

- Технологический стек: Django + Templates + HTMX, PostgreSQL
- Внешняя интеграция: библиотека `nechestniy_znak` (реализована)
- В MVP — одна площадка («Софийская Груз»), архитектура допускает множественные
- Без резервирования кодов: конфликт обнаруживается при проведении
- Ручная приписка кодов к складу при загрузке

### 2.5. Допущения и зависимости

- Библиотека `nechestniy_znak` обеспечивает корректный ответ по валидным кодам
- Формат входного файла — текстовый, по одному коду на строку
- Все пользователи аутентифицированы; анонимный доступ отсутствует
- Приложение развёртывается на одном сервере (gunicorn + nginx)

## 3. ФУНКЦИОНАЛЬНЫЕ ТРЕБОВАНИЯ

### 3.1. Загрузка DataMatrix-кодов

#### FR-1.1. Выбор склада перед загрузкой
Пользователь перед загрузкой файла выбирает склад из списка доступных. Коды приписываются к выбранному складу.
- **Вход:** ID склада
- **Выход:** Коды привязаны к складу
- **Связь:** БП-4, US-02, S-03

#### FR-1.2. Загрузка файла
Пользователь загружает текстовый файл, содержащий по одному DataMatrix-коду на строке. Система обрабатывает файл построчно.
- **Вход:** Файл (text/plain)
- **Выход:** Созданные записи TireCode или отчёт о пропусках
- **Связь:** US-01, US-03, S-03

#### FR-1.3. Дедупликация
Для каждого кода система проверяет наличие в базе по значению `qr_code` (любой статус). При обнаружении дубликата — пропуск без запроса в «Честный знак».
- **Вход:** Значение кода
- **Выход:** Пропуск + запись в лог
- **Связь:** БП-3, US-06, TC-01

#### FR-1.4. Запрос в «Честный знак»
Для нового кода система отправляет запрос через библиотеку `nechestniy_znak`. При ошибке — код пропускается с записью в лог.
- **Вход:** Значение кода
- **Выход:** Ответ с атрибутами или ошибка
- **Связь:** US-04, TC-02

#### FR-1.5. Парсинг атрибутов
Система парсит атрибуты шин из ответа «Честного знака»: `brand`, `model`, `size`, `product_name`. При неполных атрибутах (отсутствует хотя бы один из brand, model, size) — код пропускается как нераспознанный.
- **Вход:** Ответ «Честного знака»
- **Выход:** Структурированные атрибуты или пропуск
- **Связь:** БП-1, БП-2, US-05, TC-03

#### FR-1.6. Авто-создание номенклатуры
При первом встреченном сочетании `brand + model + size` система автоматически создаёт запись в `TireNomenclature`. `product_name` заполняется из ответа «Честного знака»; при отсутствии — fallback: `brand + model + size`. Не перезаписывается при повторной загрузке.
- **Выход:** Созданная или существующая номенклатура
- **Связь:** БП-1, БП-14, US-07, TC-04

#### FR-1.7. Создание TireCode
Система создаёт запись `TireCode` с привязкой к номенклатуре, складу, поставщику. Сохраняет полный ответ «Честного знака» в `honest_sign_data`.
- **Выход:** Созданная запись TireCode
- **Связь:** US-08, TC-05

#### FR-1.8. Отчёт о загрузке
По завершении загрузки система формирует отчёт:
- Создано в базе: N кодов
- Пропущено как дубликаты: M кодов
- Пропущено как нераспознанные: K кодов
- Пропущено по ошибке «Честного знака»: L кодов
- Список пропущенных кодов со значениями и причинами
- **Выход:** Страница отчёта (S-04)
- **Связь:** US-09, TC-06

#### FR-1.9. Логирование процесса загрузки
Система логирует каждый шаг обработки кода: дубликат, запрос в «Честный знак», ошибка, парсинг, создание номенклатуры, создание TireCode.
- **Связь:** US-09

### 3.2. Документы списания и выкупа

#### FR-2.1. Создание документа
Пользователь создаёт документ одного из двух типов: списание (`writeoff`) или выкуп (`buyout`). Документ создаётся в статусе `draft`.
- **Вход:** Тип документа
- **Выход:** Документ в статусе draft
- **Связь:** US-10, S-06, TC-07

#### FR-2.2. Нумерация документа
При переходе из `draft` в `saved` системе присваивается номер:
- Списание: `СП-ГГГГ-NNNNNN`
- Выкуп: `ВК-ГГГГ-NNNNNN`
- Сквозная нумерация в пределах типа и года
- Сброс счётчика в начале года
- **Связь:** БП-16, US-11, TC-08

#### FR-2.3. Добавление строки в документ
Пользователь добавляет номенклатуру в документ через поиск. При попытке добавить существующую номенклатуру — подсветка существующей строки и увеличение `quantity` на 1.
- **Вход:** ID номенклатуры
- **Выход:** Новая строка или увеличение quantity
- **Связь:** БП-15, US-12, US-13, TC-09

#### FR-2.4. Сохранение документа
Пользователь сохраняет документ. При первом сохранении — переход из `draft` в `saved` с присвоением номера. При повторном — перезапись состава.
- **Выход:** Документ в статусе saved
- **Связь:** US-14, TC-10

#### FR-2.5. Автосохранение черновика
При разрыве соединения система автоматически сохраняет черновик (фоновый POST через `beforeunload`).
- **Связь:** US-15, TC-11

#### FR-2.6. Проведение документа
Пользователь нажимает «Провести». Система выполняет атомарную транзакцию:
1. Проверка остатка по каждой строке
2. При нехватке — откат, возврат ошибки с указанием позиции и доступного количества
3. FIFO-выбор старейших активных кодов
4. Пометка кодов `is_used = True`, `is_active = False`
5. Привязка кодов к документу
6. Уменьшение счётчиков
7. Переход в статус `posted`
- **Выход:** Документ в статусе posted или ошибка
- **Связь:** БП-6, БП-7, US-16, TC-12, TC-13

#### FR-2.7. Распроведение документа
Пользователь нажимает «Распровести». Система выполняет откат:
1. Возврат кодов в активные (`is_used = False`, `is_active = True`)
2. Восстановление счётчиков
3. Отвязка кодов от документа
4. Переход в статус `saved`
- **Выход:** Документ в статусе saved
- **Связь:** БП-9, US-17, TC-14

#### FR-2.8. Пометка на удаление
Пользователь нажимает «Пометить на удаление». Система выполняет:
- Если документ проведён — распроведение + `is_deleted = True`
- Если документ сохранён — `is_deleted = True` (без распроведения)
- Переход в статус `marked_deleted`
- **Выход:** Документ в статусе marked_deleted
- **Связь:** БП-10, US-18, TC-15

#### FR-2.9. Отмена черновика
В статусе `draft` пользователь может отменить создание — сброс содержимого без сохранения.
- **Связь:** US-19

#### FR-2.10. Фильтрация списка документов
Пользователь может фильтровать список документов по:
- Типу документа (списание / выкуп)
- Статусу (сохранён / проведён / помечен на удаление)
- Площадке-источнику документа
- Площадке-источнику списания
- **Связь:** US-20, S-05, TC-16

### 3.3. Экранное отображение кодов

#### FR-3.1. Отображение кодов после проведения
После проведения документа пользователь может просмотреть закреплённые коды. До проведения — функция недоступна.
- **Ограничение:** Только для документов в статусе `posted`
- **Связь:** БП-5, US-21, TC-17

#### FR-3.2. Таблица кодов
Система отображает таблицу закреплённых кодов с пагинацией. Колонки: код, номенклатура, склад, дата загрузки.
- **Связь:** US-21, S-11

#### FR-3.3. Карточка кода
Пользователь может открыть карточку отдельного кода:
- Текстовый код в две строки
- Номенклатура (производитель + модель + размер)
- DataMatrix-изображение (размер сопоставим со спичечным коробком в книжном формате)
- **Связь:** US-22, S-12, TC-18

### 3.4. Счётчики активных кодов

#### FR-4.1. Подсчёт активных кодов
Система поддерживает счётчики активных кодов по позициям (номенклатура) и складам. Счётчики обновляются при проведении и распроведении документов.
- **Связь:** US-23, TC-19

#### FR-4.2. Отображение остатка при добавлении строки
При добавлении номенклатуры в документ система отображает текущий остаток активных кодов по данной номенклатуре на складе-источнике.
- **Связь:** US-23, TC-20

### 3.5. Управление пользователями

#### FR-5.1. CRUD пользователей
Начальник склада может создавать, просматривать, редактировать и удалять пользователей. Назначать роль и площадку.
- **Доступ:** Только `manager`
- **Связь:** US-25, US-28, S-13, TC-21

### 3.6. Списание с чужой площадки

#### FR-6.1. Списание с чужой площадки
Кладовщик может создавать документ списания, выбирая склад-источник с чужой площадки. Документ создаётся на имя кладовщика. Счётчик активных кодов уменьшается у площадки-источника списания.
- **Связь:** БП-13, US-26, TC-22

#### FR-6.2. Выкуп
Кладовщик может создать документ выкупа. Коды перевязываются на основной склад площадки кладовщика. Перезапрос «Честного знака» не выполняется.
- **Связь:** БП-8, US-27, TC-23

### 3.7. Права доступа

#### FR-7.1. Права начальника склада
- Полный доступ к документам своей площадки (создание, редактирование, проведение, распроведение, удаление)
- Документы других площадок — только чтение
- Управление пользователями
- **Связь:** БП-11, US-25, TC-24

#### FR-7.2. Права кладовщика
- Только свои документы (по авторству)
- Списание с любой площадки
- Не видит чужие документы
- Не управляет пользователями
- **Связь:** БП-12, US-26, TC-25

## 5. МОДЕЛИ ДАННЫХ

## 7. СТАТУСНАЯ МОДЕЛЬ ДОКУМЕНТА

### 7.1. Состояния

| Статус | Код | Характеристика |
|--------|-----|----------------|
| Черновик | `draft` | Номер не присвоен, автосохранение при разрыве |
| Сохранён | `saved` | Номер присвоен, редактирование состава разрешено |
| Проведён | `posted` | Коды закреплены (FIFO), редактирование запрещено |
| Помечен на удаление | `marked_deleted` | Только просмотр, is_deleted = true |

### 7.2. Переходы

| Из | В | Триггер | Действия |
|----|---|---------|----------|
| draft | saved | «Сохранить» | Присвоение номера |
| draft | — | «Отменить» | Сброс без сохранения |
| saved | saved | «Сохранить» | Перезапись состава |
| saved | posted | «Провести» | Атомарная транзакция: проверка → FIFO → пометка → счётчики |
| posted | saved | «Распровести» | Откат кодов, восстановление счётчиков |
| saved | marked_deleted | «Пометить на удаление» | is_deleted = true |
| posted | marked_deleted | «Пометить на удаление» | Распроведение + is_deleted = true |

### 7.3. Влияние на TireCode

| Переход | is_active | is_used | document | used_at |
|---------|-----------|---------|----------|---------|
| saved → posted | True → False | False → True | null → Document | null → now() |
| posted → saved | False → True | True → False | Document → null | now() → null |

### 7.4. Кнопки по статусам

| Статус | Кнопки |
|--------|--------|
| draft | Добавить строку, Сохранить, Отменить |
| saved | Добавить строку, Сохранить, Провести, Пометить на удаление |
| posted | Распровести, Экранное отображение кодов |
| marked_deleted | (только просмотр) |
