## 1. Общие принципы UI

### 1.1. Технологии интерфейса

| Компонент          | Технология                                    |
|--------------------|-----------------------------------------------|
| Фреймворк шаблонов | Django Templates                              |
| CSS-фреймворк      | Bootstrap 5                                   |
| Интерактивность    | HTMX (AJAX без написания JS)                  |
| Иконки             | Bootstrap Icons                               |
| Таблицы            | Нативные `<table>` + Bootstrap-классы         |
| Формы              | Django Forms + `crispy-bootstrap5`            |
| Уведомления        | Django `messages` (form submit), Toast (HTMX) |

### 1.2. Макет страницы

```
+----------------------------------------------------------+
|  [Логотип]  Обработка QR-кодов       [User: ФИО] [Выйти] |  ← Шапка (navbar)
+----------------------------------------------------------+
|  Загрузка кодов                                          |
|  Документы                                               |  ← Боковое меню (sidebar)
|  Пользователи (manager only)                             |
+----------------------------------------------------------+
|                                                          |
|                    Контент экрана                        |  ← Рабочая область
|                                                          |
+----------------------------------------------------------+
```

### 1.3. Цветовая кодировка статусов

| Статус              | Цвет (Bootstrap) | Бейдж   |
|---------------------|------------------|---------|
| Черновик            | `secondary`      | серый   |
| Сохранён            | `info`           | голубой |
| Проведён            | `success`        | зелёный |
| Помечен на удаление | `danger`         | красный |

### 1.4. Адаптивность

- Минимальная ширина рабочей области: **1024 px** (ориентация на десктоп/планшет)
- Мобильная верстка не входит в MVP
- Шрифт: системный, 14–16 px базовый

### 1.5. Общие правила

- Все формы защищены CSRF-токеном
- HTMX-запросы отправляют заголовок `HX-Request: true`
- Кнопки действий в карточке документа меняются в зависимости от статуса (см. диаграмму состояний)
- Модальные окна закрываются по Esc, клику на backdrop, кнопке «Закрыть»
- Пагинация: 20 строк на страницу (документы), 50 строк (коды), 10 строк (пользователи)

## 3. S-01. Экран входа

### 3.1. Назначение
Аутентификация пользователя. Точка входа в систему.

### 3.2. Макет

```
+----------------------------------------------------------+
|                                                          |
|                    Обработка QR-кодов                    |
|                                                          |
|              +----------------------------------+        |
|              |  Логин                           |        |
|              +----------------------------------+        |
|              +----------------------------------+        |
|              |  Пароль                          |        |
|              +----------------------------------+        |
|                                                          |
|              [ Войти ]                                   |
|                                                          |
+----------------------------------------------------------+
```

### 3.3. Элементы

| Элемент               | Тип                    | Описание                         |
|-----------------------|------------------------|----------------------------------|
| Поле «Логин»          | `input[type=text]`     | Имя пользователя (username)      |
| Поле «Пароль»         | `input[type=password]` | Пароль, кнопка «показать/скрыть» |
| Кнопка «Войти»        | `button[type=submit]`  | POST на `/auth/login/`           |
| Ссылка восстановления | `text`                 | Скрыта в MVP (placeholder)       |

### 3.4. Поведение

- При неверных данных — красный alert под формой: «Неверный логин или пароль»
- После успешного входа — редирект на `/` (S-02)
- Если пользователь уже аутентифицирован — авто-редирект на `/`
- Пустые поля — кнопка «Войти» disabled (HTMX-валидация)

### 3.5. URL

`/auth/login/` (GET — форма, POST — аутентификация)

## 5. S-03. Загрузка кодов

### 5.1. Назначение
Загрузка файла с DataMatrix-кодами с предварительным выбором склада.

### 5.2. Макет

```
+----------------------------------------------------------+
|  Загрузка кодов                                          |
+----------------------------------------------------------+
|                                                          |
|  Шаг 1. Выбор склада                                     |
|  +----------------------------------------+              |
|  | Склад: [ Софийская Груз — Основной  ▾ ]|              |
|  +----------------------------------------+              |
|                                                          |
|  Шаг 2. Файл с кодами                                    |
|  +----------------------------------------+              |
|  |                                        |              |
|  |     Перетащите файл сюда               |              |
|  |     или нажмите «Обзор»                |              |
|  |                                        |              |
|  |     Формат: .txt, один код на строку   |              |
|  +----------------------------------------+              |
|                                                          |
|  [ Загрузить ]                                           |
|                                                          |
+----------------------------------------------------------+
```

### 5.3. Элементы

| Элемент                   | Тип                                | Описание                                                                                                                                                      |
|---------------------------|------------------------------------|---------------------------------------------------------------------------------------------------------------------------------------------------------------|
| Выпадающий список «Склад» | `select`                           | Список складов, доступных пользователю. Для manager — все склады своей площадки. Для storekeeper — склад, к которому привязан (или все склады своей площадки) |
| Зона загрузки файла       | `input[type=file]` + drag-and-drop | Принимает `.txt`, по одному коду на строку                                                                                                                    |
| Кнопка «Загрузить»        | `button[type=submit]`              | Disabled, пока не выбран склад и файл. POST на `/upload/process/`                                                                                             |
| Текст-подсказка           | `text`                             | «Формат: .txt, один код на строку»                                                                                                                            |

### 5.4. Поведение

- Drag-and-drop подсвечивает зону рамкой при перетаскивании
- После выбора файла — отображается имя и размер
- Кнопка «Загрузить» активна только при выбранном складе и файле
- При нажатии «Загрузить»:
  1. Форма сабмитится (multipart/form-data)
  2. Экран переключается в режим прогресса (polling статуса через HTMX)
  3. По завершении — редирект на `/upload/report/{batch_id}/` (S-04)

### 5.5. Прогресс загрузки

```
+----------------------------------------------------------+
|  Загрузка кодов — обработка...                           |
+----------------------------------------------------------+
|                                                          |
|  ████████████████░░░░░░░░░░  62%                         |
|                                                          |
|  Обработано: 31 из 50 кодов                              |
|  Создано: 20  Дубликатов: 8  Ошибок: 3                   |
|                                                          |
+----------------------------------------------------------+
```

Прогресс обновляется через HTMX-опрос `/upload/status/{batch_id}/` каждые 2 секунды.

### 5.6. URL

- `/upload/` (GET — форма)
- `/upload/process/` (POST — загрузка файла)
- `/upload/status/{batch_id}/` (GET — прогресс, HTMX-фрагмент)

### 5.7. Связанные User Stories

US-01 (выбор склада), US-02 (загрузка файла), US-08 (отчёт о загрузке)

### 5.8. Связанные бизнес-правила

БП-3 (дедупликация), БП-4 (ручная приписка к складу)

## 6. S-04. Отчёт о загрузке

### 6.1. Назначение
Отображение результатов загрузки файла: сводка + список пропущенных кодов.

### 6.2. Макет

```
+----------------------------------------------------------+
|  Отчёт о загрузке                                        |
|  Файл: codes_2026-09-21.txt  |  Склад: Софийская Груз    |
+----------------------------------------------------------+
|                                                          |
|  +-------------------------------------------------------|
|  |                    СВОДКА                             |
|  +-------------------------------------------------------|
|  |  Создано в базе:          20                          |
|  |  Пропущено-дубликаты:      8                          |
|  |  Пропущено-нераспознанные:  2                         |
|  |  Пропущено-ошибка ЧЗ:      3                          |
|  |  Всего в файле:           33                          |
|  +-------------------------------------------------------|
|                                                          |
|  Пропущенные коды                                        |
|  +-------------------------------------------------------+
|  | # | Код               | Причина                       |
|  |---|-------------------|-------------------------------|
|  | 1 | 0104...0173       | Дубликат                      |
|  | 2 | 0104...0289       | Дубликат                      |
|  | 3 | 0104...0150       | Нераспознанный                |
|  | 4 | 0104...0991       | Ошибка «Честного знака»       |
|  +-------------------------------------------------------+
|                                                          |
|  [ Новая загрузка ]  [ К списку документов ]             |
|                                                          |
+----------------------------------------------------------+
```

### 6.3. Элементы

| Элемент                      | Тип      | Описание                                                                                                                        |
|------------------------------|----------|---------------------------------------------------------------------------------------------------------------------------------|
| Заголовок                    | `text`   | Имя файла и выбранный склад                                                                                                     |
| Блок «Сводка»                | Карточка | 4 счётчика + итог                                                                                                               |
| Таблица «Пропущенные коды»   | Таблица  | Колонки: №, значение кода, причина пропуска. Пагинация по 20. Если ничего не пропущено — сообщение «Все коды успешно загружены» |
| Кнопка «Новая загрузка»      | Ссылка   | → `/upload/` (S-03)                                                                                                             |
| Кнопка «К списку документов» | Ссылка   | → `/documents/` (S-05)                                                                                                          |

### 6.4. Причины пропуска

| Значение в таблице      | Бизнес-правило                              |
|-------------------------|---------------------------------------------|
| Дубликат                | БП-3 — код уже есть в базе (любой статус)   |
| Нераспознанный          | БП-2 — неполные атрибуты (brand/model/size) |
| Ошибка «Честного знака» | БП-2 — не удалось получить данные           |

### 6.5. URL

`/upload/report/{batch_id}/` (GET)

### 6.6. Связанные User Stories

US-08 (отчёт о загрузке), US-09 (список пропущенных)

### 6.7. Связанные бизнес-правила

БП-1 (авто-создание), БП-2 (нераспознанные), БП-3 (дедупликация)

БП-11 (manager — чужие только чтение), БП-12 (кладовщик — чужие не видит), БП-13 (списание с чужой площадки)

## 8. S-06. Создание документа

### 8.1. Назначение
Выбор типа документа (списание / выкуп) перед переходом в карточку черновика.

### 8.2. Макет

```
+----------------------------------------------------------+
|  Создание документа                                       |
+----------------------------------------------------------+
|                                                          |
|  Выберите тип документа:                                 |
|                                                          |
|  +-----------------------+    +-----------------------+   |
|  |    Списание            |    |     Выкуп             |   |
|  |                        |    |                       |   |
|  |    СП-ГГГГ-NNNNNN      |    |    ВК-ГГГГ-NNNNNN    |   |
|  |                        |    |                       |   |
|  |  Списание кодов        |    |  Выкуп кодов с        |   |
|  |  со склада             |    |  ответственного       |   |
|  |                        |    |  хранения             |   |
|  +-----------------------+    +-----------------------+   |
|                                                          |
+----------------------------------------------------------+
```

### 8.3. Элементы

| Элемент | Тип | Описание |
|---------|-----|----------|
| Карточка «Списание» | Кнопка-ссылка | → `/documents/create/?type=writeoff` → редирект в S-07 |
| Карточка «Выкуп» | Кнопка-ссылка | → `/documents/create/?type=buyout` → редирект в S-07 |

### 8.4. Логика

- При клике создаётся документ в статусе `draft` (без номера)
- Автозаполнение полей:
  - `doc_type` — из URL-параметра
  - `author` — текущий пользователь
  - `source_platform` — площадка автора
  - `source_warehouse` — для списания: выбор кладовщиком; для выкупа: склад ОХ (выбор из складов типа `oh`)
  - `target_warehouse` — для выкупа: Основной склад площадки автора; для списания: null
- Редирект на карточку документа (S-07)

### 8.5. URL

`/documents/create/` (GET с параметром `?type=writeoff|buyout`)

- При следующем входе в документ — восстановление состава из последнего автосохранения

### 10.6. Поведение при проведении

- Кнопка «Провести» → POST `/documents/{id}/post/`
- Серверная атомарная транзакция (БП-6, БП-7):
  1. Проверка остатка по каждой строке
  2. При нехватке — возврат с ошибкой:

     |  Документ вернётся в статус «Сохранён»                |

## 16. S-14. Модальное окно поиска номенклатуры

### 16.1. Назначение
Поиск и выбор номенклатуры при добавлении строки в документ. Вызывается из S-07 (Черновик) и S-08 (Сохранён).

### 16.2. Макет

```
+----------------------------------------------------------+
|  Добавить номенклатуру                            [ ✕ ]   |
+----------------------------------------------------------+
|  Поиск: [ Введите brand, модель или размер...     ] [🔍]  |
+----------------------------------------------------------+
|  Результаты                                               |
|  +------------------------------------------------------+
|  | # | Производитель | Модель     | Размер    | Остаток |
|  |---|----------------|------------|-----------|---------|
|  | 1 | Michelin       | Primacy 4  | 205/55 R15|   12    |
|  | 2 | Michelin       | Primacy 4  | 215/55 R17|    3    |
|  | 3 | Continental    | Conti...   | 195/65 R15|    8    |
|  +------------------------------------------------------+
|                                                          |
|  « 1 2 »  Показано 1–10 из 23                            |
+----------------------------------------------------------+
|  [ Отмена ]  [ Добавить ]                                 |
+----------------------------------------------------------+
```

### 16.3. Элементы

| Элемент | Тип | Описание |
|---------|-----|----------|
| Поле поиска | `input[type=text]` | Поиск по brand, model, size. HTMX-обновление результатов при вводе (debounce 300ms) |
| Таблица результатов | Таблица | Производитель, модель, размер, остаток активных кодов на выбранном складе. Селект-радио для выбора |
| Кнопка «Добавить» | Кнопка | Добавляет выбранную номенклатуру в документ |
| Кнопка «Отмена» | Кнопка | Закрывает модальное окно |

### 16.4. Поведение при добавлении (БП-15)

| Ситуация | Поведение |
|----------|-----------|
| Номенклатуры нет в документе | Создаётся новая строка, quantity=1, модальное окно закрывается |
| Номенклатура уже есть в документе | Новая строка не создаётся. Существующая строка подсвечивается (жёлтым), quantity увеличивается на 1. Модальное окно закрывает, показывается toast: «Номенклатура уже в документе, количество увеличено» |
| Ничего не выбрано | Кнопка «Добавить» disabled |

### 16.5. Остаток в результатах

- Колонка «Остаток» показывает количество активных кодов по каждой номенклатуре на выбранном складе-источнике
- Если остаток = 0 — строка помечена серым, tooltip «Нет активных кодов на складе»
- Добавление номенклатуры с нулевым остатком — разрешено (код может появиться при следующей загрузке), но при проведении будет ошибка нехватки

### 16.6. URL

`/nomenclature/search/?q=...&warehouse_id=...` (GET, HTMX-фрагмент — HTML таблицы результатов)

US-12 (добавление строк), US-13 (дубликаты — подсветка + quantity++)

### 16.8. Связанные бизнес-правила
