Система обработки DataMatrix-кодов (MVP)
Версия: 1.0
Дата: 20 сентября 2026 г.

================================================================
СОДЕРЖАНИЕ
================================================================
1. Tire_nomenclature — Номенклатура шин
2. TireCode — Индивидуальный DataMatrix-код

================================================================
1. TIRE_NOMENCLATURE — НОМЕНКЛАТУРА ШИН
================================================================
Назначение: справочник номенклатурных позиций. Каждое уникальное
сочетание «производитель + модель + размер» — отдельная позиция.
Создаётся автоматически при загрузке кода с новыми атрибутами.

Поля:
+------------------+----------------+-------------------------------------------+---------------------------+
| Поле             | Тип            | Описание                                  | Ограничения               |
+------------------+----------------+-------------------------------------------+---------------------------+
| brand            | Строка (100)   | Производитель (из ответа «Честного знака»)| Обязательное              |
| model            | Строка (100)   | Модель + индекс нагрузки                  | Обязательное              |
| size             | Строка (50)    | Размер в формате 205/55 R15               | Обязательное              |
| product_name     | Строка (100)   | Наименование товара                       | Необязательное            |
| is_active        | Логическое     | Активна ли позиция (для скрытия из списка)| По умолчанию = true       |
| created_at       | Дата+время     | Дата создания                             | Авто, при создании        |
| updated_at       | Дата+время     | Дата последнего изменения                 | Авто, при сохранении      |
+------------------+----------------+-------------------------------------------+---------------------------+

Ограничение уникальности: (brand, model, size) — не может быть двух
позиций с одинаковым сочетанием.

Бизнес-правила:
- Создаётся автоматически при первом встреченном сочетании
  brand + model + size при загрузке файла.
- Если атрибуты не распознаны (нет brand, model или size) — код
  пропускается, номенклатура не создаётся.
- Пользователь не создаёт и не редактирует номенклатуру вручную.
- Удаление номенклатуры не предусмотрено (можно скрыть через
  is_active = false).

================================================================
2. TIRECODE — ИНДИВИДУАЛЬНЫЙ DATAMATRIX-КОД
================================================================
Назначение: хранение конкретного DataMatrix-кода с привязкой к
номенклатуре, складу, поставщику, статусу и документу.

Поля:
+------------------+----------------+-------------------------------------------+---------------------------+
| Поле             | Тип            | Описание                                  | Ограничения               |
+------------------+----------------+-------------------------------------------+---------------------------+
| qr_code          | Строка (100)   | Значение DataMatrix-кода                  | Уникальное, обязательное  |
| nomenclature     | Ссылка (FK)    | Ссылка на Tire_nomenclature                | Обязательное              |
| warehouse        | Ссылка (FK)    | Склад, к которому приписан код             | Обязательное              |
| supplier         | Ссылка (FK)    | Поставщик (только для складов ОХ)         | Необязательное            |
| is_active        | Логическое     | Код активен (доступен для списания)        | По умолчанию = true       |
| is_used          | Логическое     | Код использован (списан проведённым       | По умолчанию = false      |
|                  |                | документом)                                |                           |
| honest_sign_data | JSON           | Полный ответ «Честного знака»              | Необязательное            |
| created_at       | Дата+время     | Дата загрузки в систему (для FIFO)         | Авто, при создании        |
| used_at          | Дата+время     | Дата пометки использованным               | Заполняется при проведении|
| document         | Ссылка (FK)    | Документ, в котором код списан            | Необязательное,           |
|                  |                |                                           | заполняется при проведении|
+------------------+----------------+-------------------------------------------+---------------------------+

Бизнес-правила:
- Дедупликация: если qr_code уже есть в системе (с любым статусом) —
  код пропускается, повторный запрос в «Честный знак» не отправляется.
- is_active = true и is_used = false — код доступен для списания.
- is_active = true и is_used = true — код списан проведённым документом.
- При проведении документа: выбираются старейшие активные коды
  по позиции (сортировка по created_at, затем по ID), помечаются
  is_used = true, привязываются к document, заполняется used_at.
- При распроведении документа: is_used = false, document = null,
  used_at = null — код возвращается в активный пул.
- FIFO: первыми списываются коды с меньшим created_at; внутри одних
  суток — с меньшим ID (порядок автоинкремента).
- Логирование: каждый код логируется при загрузке (создан / пропущен-
  дубликат / пропущен-нераспознан / пропущен-ошибка «Честного знака»).

================================================================
3. PLATFORM — ПЛОЩАДКА
================================================================
Назначение: место хранения, объединяющее склады. В MVP — одна
площадка «Софийская Груз». Архитектура допускает добавление
второй площадки «Софийская Легковой» без изменения структуры.

Поля:
+------------------+----------------+-------------------------------------------+---------------------------+
| Поле             | Тип            | Описание                                  | Ограничения               |
+------------------+----------------+-------------------------------------------+---------------------------+
| name             | Строка (100)   | Название площадки                         | Уникальное, обязательное  |
| created_at       | Дата+время     | Дата создания                             | Авто, при создании        |
+------------------+----------------+-------------------------------------------+---------------------------+

Бизнес-правила:
- Площадка — самостоятельная сущность, не склад.
- Каждой площадке принадлежит один Основной склад и может
  принадлежать несколько складов ОХ.
- Пользователь привязан к одной площадке (через расширение User).
- В MVP работает только площадка «Софийская Груз».

================================================================
4. WAREHOUSE — СКЛАД (дополненная модель)
================================================================
Назначение: склад внутри площадки. Бывает двух типов: Основной
и Ответственное хранение (ОХ).

Поля:
+------------------+----------------+-------------------------------------------+---------------------------+
| Поле             | Тип            | Описание                                  | Ограничения               |
+------------------+----------------+-------------------------------------------+---------------------------+
| name             | Строка (100)   | Название склада                           | Уникальное, обязательное  |
| warehouse_type   | Выбор          | Тип: «Основной склад» или «ОХ»            | Обязательное              |
| platform         | Ссылка (FK)    | Площадка, которой принадлежит склад       | Обязательное              |
| supplier         | Ссылка (FK)    | Поставщик (только для складов ОХ)         | Необязательное            |
| created_at       | Дата+время     | Дата создания                             | Авто, при создании        |
+------------------+----------------+-------------------------------------------+---------------------------+

Типы складов:
- main — Основной склад площадки. Для документов списание и выкуп —
  как источник и получатель.
- oh — Ответственное хранение. Для документа выкуп — как источник.
  Каждый склад ОХ связан с конкретным поставщиком.

Бизнес-правила:
- У каждой площадки один склад типа «Основной».
- Складов типа «ОХ» может быть несколько (по числу поставщиков).
- Склад ОХ без указанного поставщика недопустим.
- Коды приписываются к конкретному складу при ручной загрузке
  (пользователь выбирает склад перед загрузкой файла).

================================================================
5. SUPPLIER — ПОСТАВЩИК (без изменений)
================================================================
Назначение: справочник поставщиков (владельцев при ответственном
хранении).

Поля:
+------------------+----------------+-------------------------------------------+---------------------------+
| Поле             | Тип            | Описание                                  | Ограничения               |
+------------------+----------------+-------------------------------------------+---------------------------+
| name             | Строка (255)   | Название поставщика                       | Уникальное, обязательное  |
| created_at       | Дата+время     | Дата создания                             | Авто, при создании        |
+------------------+----------------+-------------------------------------------+---------------------------+

Бизнес-правила:
- Поставщик связан со складом ОХ (один поставщик = один склад ОХ).
- В MVP — три поставщика: «Поставщик-1», «Поставщик-2», «Поставщик-3».
- Справочник поставщиков общий для всех площадок.

================================================================
6. DOCUMENT — ДОКУМЕНТ СПИСАНИЯ / ВЫКУПА
================================================================
Назначение: документ, описывающий операцию списания или выкупа
кодов. Содержит состав строк с номенклатурой и количеством.
При проведении — закрепляет конкретные коды за документом.

Поля:
+------------------+----------------+-------------------------------------------+---------------------------+
| Поле             | Тип            | Описание                                  | Ограничения               |
+------------------+----------------+-------------------------------------------+---------------------------+
| doc_type         | Выбор          | Тип документа: «Списание» или «Выкуп»     | Обязательное              |
| number           | Строка (50)    | Номер документа                           | Присваивается при         |
|                  |                |                                           | переходе в «Сохранён»     |
| status           | Выбор          | Статус документа (см. ниже)               | Обязательное              |
| author           | Ссылка (FK)    | Пользователь, создавший документ          | Обязательное              |
| source_platform  | Ссылка (FK)    | Площадка-источник документа (на какой      | Обязательное              |
|                  |                | площадке создан документ)                 |                           |
| writeoff_platform| Ссылка (FK)    | Площадка-источник списания (с какой        | Обязательное              |
|                  |                | площадки списываются коды)                |                           |
| source_warehouse | Ссылка (FK)    | Склад-источник кодов                       | Обязательное              |
| target_warehouse | Ссылка (FK)    | Склад-получатель (для выкупа — основной    | Для выкупа — обязательно, |
|                  |                | склад площадки автора; для списания —     | для списания — пусто)     |
|                  |                | не используется)                           |                           |
| is_deleted       | Логическое     | Документ помечен на удаление              | По умолчанию = false      |
| created_at       | Дата+время     | Дата создания                             | Авто, при создании        |
| updated_at       | Дата+время     | Дата последнего изменения                 | Авто, при сохранении      |
| conducted_at     | Дата+время     | Дата проведения                           | Заполняется при переходе  |
|                  |                |                                           | в «Проведён»              |
+------------------+----------------+-------------------------------------------+---------------------------+

Статусы документа:
- DRAFT — Черновик (не сохранён). Номер не присвоен. Можно добавлять
  строки, сохранять, отменять.
- SAVED — Сохранён. Номер присвоен. Можно добавлять строки, проводить,
  помечать на удаление.
- CONDUCTED — Проведён. Коды закреплены за документом. Можно
  распровести, отобразить коды на экране.
- DELETED — Помечен на удаление (= распроведение + is_deleted = true).
  Только просмотр.

Два поля площадок — зачем:
- source_platform — для фильтра «кто создал документ» (сотрудник
  какой площадки). Совпадает с площадкой автора.
- writeoff_platform — для фильтра «откуда списаны коды» (с какой
  площадки). Может отличаться от source_platform при межскладском
  списании.

Бизнес-правила:
- При списании: source_warehouse — склад, с которого списываются коды;
  target_warehouse — не используется.
- При выкупе: source_warehouse — склад ОХ поставщика; target_warehouse
  — Основной склад площадки автора.
- Проведённый документ не редактируется. Для изменений — распроведение
  (возврат в SAVED), затем редактирование и повторное проведение.
- Помечен на удаление = распроведение (коды возвращаются в активный
  пул, счётчики восстанавливаются) + is_deleted = true.
- При проведении — атомарная транзакция:
  1. Проверка остатка по каждой строке (количество_запрошено <=
     количество_активных_кодов по позиции на складе-источнике).
  2. При нехватке хотя бы по одной строке — откат, ошибка с указанием
     позиции и доступного количества. Документ остаётся в SAVED.
  3. При достаточности — выбор старейших кодов (FIFO), пометка
     is_used = true, привязка к документу, заполнение used_at.
  4. Перевод в CONDUCTED, заполнение conducted_at.
- Автосохранение черновика при разрыве соединения.

================================================================
7. DOCUMENTITEM — СТРОКА ДОКУМЕНТА
================================================================
Назначение: строка документа с номенклатурой и количеством кодов
к списанию/выкупу.

Поля:
+------------------+----------------+-------------------------------------------+---------------------------+
| Поле             | Тип            | Описание                                  | Ограничания               |
+------------------+----------------+-------------------------------------------+---------------------------+
| document         | Ссылка (FK)    | Документ, которому принадлежит строка    | Обязательное              |
| nomenclature     | Ссылка (FK)    | Номенклатурная позиция                    | Обязательное              |
| quantity         | Целое число    | Количество кодов к списанию/выкупу        | Обязательное, > 0         |
| created_at       | Дата+время     | Дата создания строки                      | Авто, при создании        |
+------------------+----------------+-------------------------------------------+---------------------------+

Бизнес-правила:
- Одна строка = одна номенклатурная позиция + количество кодов.
- Дубликаты номенклатуры в одном документе недопустимы (или
  объединяются в одну строку с суммарным количеством — на усмотрение
  реализации).
- При проведении: система выбирает quantity старейших активных кодов
  по данной номенклатуре на складе-источнике.
- Количество не может быть 0 или отрицательным.
- Добавление строк возможно в статусах DRAFT и SAVED.
- В статусе CONDUCTED строки не редактируются.

================================================================
8. USER — ПОЛЬЗОВАТЕЛЬ (расширение: площадка + роль)
================================================================
Назначение: расширение стандартной модели User Django для привязки
пользователя к площадке и назначения роли.

Поля (дополнительно к стандартным полям User):
+------------------+----------------+-------------------------------------------+---------------------------+
| Поле             | Тип            | Описание                                  | Ограничения               |
+------------------+----------------+-------------------------------------------+---------------------------+
| platform         | Ссылка (FK)    | Площадка, к которой привязан пользователь | Обязательное              |
| role             | Выбор          | Роль: «Начальник склада» или «Кладовщик»  | Обязательное              |
+------------------+----------------+-------------------------------------------+---------------------------+

Роли:
- MANAGER — Начальник склада:
  - Управляет кладовщиками своей площадки (добавляет, блокирует).
  - Полный доступ к документам своей площадки (создание, редактирование
    до проведения, проведение, распроведение, пометка на удаление).
  - Документы других площадок — только чтение.
  - Может списывать коды с любой площадки (счётчик уменьшается
    у площадки-источника списания).
  - На площадке один активный начальник.

- STOREKEEPER — Кладовщик:
  - Создаёт и редактирует только свои документы.
  - Не может проводить чужие документы.
  - Может списывать коды с любой площадки (счётчик уменьшается
    у площадки-источника списания).
  - Количество кладовщиков не ограничено.

Бизнес-правила:
- Пользователь привязан ровно к одной площадке.
- Роль определяет права доступа к документам.
- source_platform документа = platform автора.
- Начальник видит все документы своей площадки + (по желанию)
  документы других площадок в режиме только чтение.
- Кладовщик видит только свои документы.
- В MVP — один кладовщик.

================================================================
СТАТУСНАЯ МОДЕЛЬ ДОКУМЕНТА
================================================================

DRAFT (черновик, не сохранён)
  │  кнопки: «Добавить строку», «Сохранить», «Отменить»
  │  «Отменить» → сброс, удаление черновика
  │  «Сохранить» → переход в SAVED
  ▼
SAVED (сохранён, номер присвоен)
  │  кнопки: «Добавить строку», «Сохранить», «Провести», «Пометить на удаление»
  │  «Провести» → проверка остатка → успех → CONDUCTED
  │                                    → нехватка → остаётся SAVED + ошибка
  │  «Пометить на удаление» → DELETED
  │  Автосохранение при разрыве соединения → остаётся SAVED
  ▼
CONDUCTED (проведён, коды закреплены)
  │  кнопки: «Распровести», «Экранное отображение кодов»
  │  «Распровести» → возврат кодов в активный пул → SAVED
  │  «Экранное отображение» → карточки кодов с прокруткой
  ▼
DELETED (помечен на удаление)
     = распроведение (коды возвращаются) + is_deleted = true
     Только просмотр.

================================================================
ОТКРЫТЫЕ ВОПРОСЫ
================================================================
1. Дубликаты номенклатуры в одном документе: запрещать или
   объединять в одну строку с суммарным количеством? (DocumentItem)
2. Поле number документа: формат нумерации (сквозной, по году,
   по типу документа)? (Document)
3. Поле product_name в Tire_nomenclature: заполняется из
   «Честного знака» всегда, или только при наличии? (Tire_nomenclature)
